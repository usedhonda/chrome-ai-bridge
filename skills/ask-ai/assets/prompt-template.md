## Evidence

Include observed errors, reproduction steps, and what has already been checked. Distinguish observations from assumptions. For private Gemini work, select the relevant source files and excerpts through `--context`; a private URL alone is not readable code context.

## Requested work

State the specific implementation or review questions. Include acceptance criteria and useful verification commands. Do not ask the provider to invent test results, inaccessible file contents, branch names already created, or PR URLs.

## Follow-up context

For a continuation, name the remaining issue and any changes since the preceding request. Keep the same CAB project/provider conversation. Include refreshed private Gemini code context for the affected files.
